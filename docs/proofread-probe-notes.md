# `/proofread` 侦察笔记

## 当前页面定位

- 路由：`https://review.newidea.pro/proofread`
- 页面标题：`综述写作工作台`
- 所处流程：`STEP 3 初稿校对`

## 当前可稳定识别的结构

### 顶部 CTA

当前已观察到以下稳定按钮文本：

- `返回提纲`
- `折叠提纲`
- `完成校对`
- `本地保存`

这些按钮适合作为 `probe/state` 的全局控制区读模型。

### 段落校对卡片

主内容区由一组连续 `section` 组成，每张卡片通常具备：

- 第一行提示语：
  - `点击本段进入编辑校对`
  - 或 `请校对本段内容`
- 第二行通常是段落标题，如 `Abstract`、`Introduction`、`Conclusion`
- 后续正文为当前段的英文全文预览

已观察到：

- 当前活动段提示语会显示为 `点击本段进入编辑校对`
- 其余未激活段通常显示为 `请校对本段内容`
- 卡片顺序与左侧提纲顺序大体一致

因此第一阶段可用 `section` + 首行提示语 作为稳定锚点。

### 编辑态卡片

当页面已进入某段的编辑态时，当前观察到以下稳定特征：

- 目标卡片 class 会从 `border-transparent` 切换为 `border-primary`
- 同时常伴随 `caret-inherit`、`cursor-auto`
- 卡片内部会出现编辑态按钮：
  - `确认校对`
  - `AI 改写`

这说明“编辑态”本身是可以被 bridge 稳定识别的，只是进入编辑态的前置自动化链路仍未完全打通。

### AI 改写面板

在编辑态中点击 `AI 改写` 后，当前观察到以下结构：

- 额外需求输入框：placeholder 为 `请输入额外需求`
- 按钮：
  - `一键重写`
  - `一键复制`
  - `替换原文`

其中：

- `一键复制`、`替换原文` 在未生成结果前可能是 disabled
- 触发 `一键重写` 后，当前真实页面观察到约 45 秒内这两个按钮会解除 disabled
- 点击 `替换原文` 后会先弹出确认框，按钮为 `取消 / 确定`
- 确认后，当前编辑段正文会被改写结果替换
- 这套结构适合做 `rewrite-prompt` 与 `editor-button` 命令

### 提纲侧栏

页面左侧可见全文标题和提纲条目，例如：

- `Abstract`
- `Keywords`
- `Introduction`
- `Conclusion`
- `1.1 ...`
- `2.1 ...`

当前 bridge 还没有直接做侧栏精确建模，只先在 `probe` 里做采样输出。

## 当前 bridge 输出

`probe` 重点输出：

- 是否在 `/proofread`
- 顶部 CTA 可见性
- 段落卡片总数
- 当前活动段
- 提纲标题采样

`state` 重点输出：

- 当前 URL / pathname / scrollY
- 活动段
- 段落卡片列表前若干项
- 顶部 CTA 状态
- 当前编辑态
- AI 改写面板状态

`select-section <paragraphIndex>` 当前行为：

- 使用 0-based 段落顺序
- 对目标卡片派发一组 pointer/mouse 事件
- 成功信号为：
  - 提示语切成 `点击本段进入编辑校对`
  - 或卡片 class 出现 `hover:bg-secondary`
- 该状态当前观察为瞬时态，不保证在后续单独 `state` 调用中持续存在

`rewrite-prompt <text>` 当前行为：

- 向 `请输入额外需求` 文本框写值
- 自动触发 `input / change`

`editor-button <name>` 当前行为：

- 点击当前编辑态可见按钮
- 当前支持：
  - `确认校对`
  - `AI 改写`
  - `一键重写`
  - `一键复制`
  - `替换原文`

`state / probe` 中的编辑态补充信号：

- `editorButtons.length > 0` 可视为已进入编辑态
- `rewriteReady = true` 表示 `一键复制 / 替换原文` 至少有一个已可点击
- `替换原文` 确认后，`一键重写 / 一键复制 / 替换原文` 会消失，编辑态通常回落为 `确认校对 / AI 改写`

## 关于进入编辑态的现状

当前已在真实页面测试以下交互：

- 单击卡片
- 双击卡片
- 点击标题
- 点击正文段落
- 单击后按 `Enter`

早先结论：

- 以上动作都会把目标卡片切到高亮/活动提示态
- 但不会出现新的可输入控件、持久焦点、额外操作按钮或可见对话框
- 因此目前还不能把这一步定义为“进入持久编辑态”

补充结论：

- 一旦用户手动进入编辑态，bridge 已经可以稳定识别该状态
- AI 改写面板的输入框与按钮也已具备稳定 DOM 锚点

## 暂不做的内容

当前先不实现以下能力：

- 段落正文替换
- 接受 / 拒绝单段校对建议
- 与页面内部编辑器、diff 视图或弹窗交互

原因：

- 还未确认稳定的段落身份语义，是 `index`、标题，还是更底层 DOM / React 锚点
- 还未验证校对后的成功信号是 DOM 改写、按钮状态变化，还是页面跳转

## 下一阶段建议

后续如要扩展 `/proofread` 写操作，建议按这个顺序推进：

1. 先补“点击某段并确认进入编辑态”
2. 再定义段落身份模型，例如 `paragraphIndex`
3. 最后再接接受建议 / 保存 / 完成校对等破坏性动作
